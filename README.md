# funnel-project · ОП.03 «Информационные технологии»

Ваш репозиторий на всю дисциплину. Сюда вы сдаёте домашние работы: бланки
и скриншоты. Он остаётся у вас и после того, как дисциплина закончится.

## С чего начать

**1. Сделайте репозиторий своим.** Нажмите **Use this template → Create
a new repository** и назовите его `funnel-project`. Кнопка **Fork** для
этого не подходит: форк остаётся привязан к чужому репозиторию.

**2. Откройте его у себя.** Нужен только git и аккаунт GitHub.

```bash
git clone <адрес вашего репозитория> funnel-project
cd funnel-project
```

Всё то же самое делается мышкой в VS Code, без терминала. Как именно,
разобрано со скриншотами [коротко](docs/git/README.md)
и [подробно](docs/git/FULL.md).

## Домашние работы

| № | Папка | Что сдаёте | Ветка |
|---|---|---|---|
| 1 | `lesson_01` | три события на сайте, путь пользователя, точка потери данных | `hw-01` |
| 2 | `lesson_02` | где бизнес теряет клиентов: воронка и настройка GA4 | `hw-02` |
| 3 | `lesson_03` | скриншоты: тег на сайте, источник перехода и отчёты GA4 | `hw-03` |

Что именно делать, написано в файле `README.md` внутри папки задания.
Там же лежит бланк `homework_NN.md`: вы вписываете свои ответы в готовые
таблицы.

## Как сдать

Правило простое: **одно задание — одна ветка — один запрос на слияние.**

```bash
git switch main
git pull
git switch -c hw-01
# заполняем lesson_01/homework_01.md, кладём кадры в lesson_01/screens/
git add lesson_01
git commit -m "hw-01: три события, путь пользователя, точка потери данных"
git push -u origin hw-01
```

Дальше на GitHub открываете **Pull Request** в свою `main` и пишете, что
сделали. Слить его вы можете сами после проверки.

Сроки, требования к скриншотам и чек-лист перед отправкой собраны
в [docs/SUBMIT.md](docs/SUBMIT.md).

## Что проверяется в любой работе

Шапка бланка заполнена, файл лежит в папке своего задания, скриншоты
в `screens/` и открываются по ссылкам из бланка, пустых строк-заготовок
не осталось, у источников записан полный адрес.

Полный список требований к оформлению лежит
в [HOMEWORK_TEMPLATE.md](HOMEWORK_TEMPLATE.md).

## Чего здесь быть не должно

- Токены, ключи, пароли, строки подключения. Их место в хранилище
  секретов сервиса.
- Экспорт workflow с секретами внутри: выгружайте очищенный.
- Лишние личные данные в тестовых заявках и на скриншотах.

Файл `.gitignore` уже ловит частые имена (`*.secret`, `credentials*.json`,
`.env`), но перед отправкой посмотрите коммит глазами.

## Про ИИ

Спрашивать модель можно: идеи, структура работы, формулировки. Но
источником она не считается, поэтому под каждым фактом, цифрой и случаем
нужна ссылка на исходный материал. Наблюдения в браузере, настройку
сервисов и скриншоты вы делаете сами.

Показатели компаний придумывать нельзя. Если их нет в открытых
источниках, так и пишите: «точные показатели в открытом источнике
не приведены».

В каждом бланке есть раздел про использование ИИ, и заполнять его нужно
честно. Работу, собранную из одного текста нейросети, без источников
и скриншотов, преподаватель не принимает.
