# funnel-project · ОП.03 «Информационные технологии»

Ваш рабочий репозиторий на всю дисциплину. Здесь лежит всё, что собрано на
парах: карты воронки, журналы событий, справочники меток, паспорта ресурсов
аналитики, экспорты workflow, тестовые payload, таблицы заявок, кадры
DebugView и Preview, отчёты и test matrix. К концу курса это и есть проект
«Цифровая воронка и автоматизация заявок», который вы разворачиваете с нуля
и защищаете.

## Сделать репозиторий своим

Нажмите **Use this template → Create a new repository**, назовите
`funnel-project` и выберите видимость. У вас появится собственный
репозиторий с чистой историей — он остаётся у вас и после дисциплины.
Форк для этого не подходит: он остаётся привязан к исходному репозиторию.

## Установка

Нужен только **git** и аккаунт **GitHub**. Всё остальное — сервисы в
браузере; n8n и Bruno ставятся на первой паре раздела 3, тогда же и
разберём как.

```bash
git clone <адрес вашего репозитория> funnel-project
cd funnel-project
```

Всё то же самое можно делать мышкой в VS Code, без терминала. Разбор
со скриншотами: [коротко](docs/git/README.md) — основные операции
с размеченными кадрами, [подробно](docs/git/FULL.md) — каждый шаг,
включая типичные ошибки.

## Структура

```
lesson_01/            вводное занятие: карта курса — домашнее задание
lesson_02/            цифровая воронка: карта, журнал событий, два задания
lesson_03/            UTM-метки: справочник, ссылки, два задания
lesson_04/            Google Analytics 4: паспорт ресурса и Measurement ID
lesson_05/            свой сайт, Vercel и Google Tag: адреса и проверки
docs/SUBMIT.md        порядок сдачи и чек-лист перед отправкой
docs/git/             разбор работы с git и GitHub со скриншотами
```

На каждое занятие — своя папка. Внутри уже лежат бланки: их нужно заполнять,
а не создавать с нуля. Материалы занятия — схему, payload, экспорт workflow,
кадры — я выдаю и мы собираем на паре, вы кладёте их в ту же папку рядом
с бланками.

Папку для нового занятия создаёте копией последней:
`cp -r lesson_05 lesson_06` (на Windows —
`Copy-Item -Recurse lesson_05 lesson_06`).

Что сдавать и что проверяется — в `README.md` внутри папки занятия.

## Как сдавать

**Одно задание — одна ветка — один запрос на слияние.** Ветка называется
по номеру папки занятия.

| Занятие | Папка | Первое задание | Исследовательское задание |
|---|---|---|---|
| Вводное | `lesson_01` | `homework_01.md` · `hw-01` | — |
| Цифровая воронка | `lesson_02` | `homework_01.md` · `hw-02` | `research_01.md` · `hw-02-research` |
| UTM-метки | `lesson_03` | `homework_02.md` · `hw-03` | `research_02.md` · `hw-03-research` |
| Google Analytics 4 | `lesson_04` | сдаётся `ga4_setup.md` на паре | — |
| Свой сайт и Google Tag | `lesson_05` | сдаётся `site.md` на паре | — |

```bash
git switch main
git pull
git switch -c hw-02
git add lesson_02
git commit -m "hw-02: журнал событий на втором сайте, сравнение, гипотеза"
git push -u origin hw-02
```

Дальше на GitHub открываете **Pull Request** в свою `main` и коротко
пишете, что сделано. Merge делаете сами после проверки. Срок первого
задания — до начала следующего занятия.

Полный порядок, сроки, печать бланков в PDF, чек-лист и разбор частых
ошибок — [docs/SUBMIT.md](docs/SUBMIT.md).

## Отдельный репозиторий сайта

На занятии 5 вы публикуете свой сайт. Его код живёт **не здесь**, а в копии
шаблона [ga4-analytics-lab](https://github.com/MaximBytecamp/ga4-analytics-lab),
созданной той же кнопкой **Use this template**. В этот репозиторий попадают
только адреса, идентификаторы и кадры проверок — файл `lesson_05/site.md`.
Код сайта сюда не копируется: у него своя история и своя связь с Vercel.

## Что не кладём в репозиторий

- **Токены, ключи API, пароли, строки подключения.** Секреты живут в
  credentials store сервиса, а не в файлах и не в экспорте workflow.
- **Экспорт workflow с секретами внутри.** Перед коммитом workflow
  выгружается очищенным (sanitized export).
- **Лишние персональные данные** в тестовых payload и кадрах —
  замазываем или используем учебные значения.
- **Слитые базы данных** — по исследовательским заданиям это отдельно
  запрещено, независимо от качества разбора.

Файл `.gitignore` уже исключает частые опасные имена (`*.secret`,
`credentials*.json`, `.env`), но проверять коммит перед отправкой всё
равно нужно глазами.

## Правила

- ИИ в проекте — только как отдельный проверяемый шаг: классификация
  обращения с проверкой правилами и fallback. Настройку и маршрут вы
  собираете сами.
- В оформлении отчётов ИИ можно после собственной работы: причесать
  формулировки, оформить `.md`. Содержание остаётся вашим. В каждом бланке
  есть раздел про использование ИИ — он заполняется честно.
- По исследовательским заданиям любую цифру и любое название из ответа
  модели проверяйте по первоисточнику: модели уверенно называют
  несуществующие исследования и выдуманные суммы штрафов.
- На защите решение должно воспроизводиться у другого человека после
  `git clone` и импорта workflow.
