# funnel-project · ОП.03 «Информационные технологии»

Ваш рабочий репозиторий на всю дисциплину. Сюда сдаются домашние работы
и складывается всё, что собрано на парах: журналы событий, схемы воронки,
скриншоты GA4, экспорты workflow, таблицы заявок и отчёты.

## Сделать репозиторий своим

Нажмите **Use this template → Create a new repository**, назовите
`funnel-project` и выберите видимость. У вас появится собственный
репозиторий с чистой историей — он остаётся у вас и после дисциплины.
Форк для этого не подходит: он остаётся привязан к исходному репозиторию.

## Установка

Нужен только **git** и аккаунт **GitHub**.

```bash
git clone <адрес вашего репозитория> funnel-project
cd funnel-project
```

Всё то же самое делается мышкой в VS Code, без терминала. Разбор
со скриншотами: [коротко](docs/git/README.md), [подробно](docs/git/FULL.md).

## Домашние работы

| № | Папка | Что сдаётся | Бланк | Ветка |
|---|---|---|---|---|
| 1 | `lesson_01` | три действия на сайте, путь пользователя из 5 шагов, точка потери данных | `homework_01.md` | `hw-01` |
| 2 | `lesson_02` | где бизнес теряет клиентов: исследование воронки + структура GA4 до Measurement ID | `homework_02.md` | `hw-02` |
| 3 | `lesson_03` | тег на сайте, источник перехода и отчёты GA4 — скриншотами | `homework_03.md` | `hw-03` |

Условия, объёмы, список скриншотов и критерии оценки — в `README.md` внутри
папки задания. Бланк там же: его заполняют, а не создают с нуля.

`HOMEWORK_TEMPLATE.md` в корне — образец шапки с ФИО и группой и общие
требования к оформлению. Сдавать его не нужно.

## Как сдать

**Одно задание — одна ветка — один запрос на слияние.**

```bash
git switch main
git pull
git switch -c hw-01
# заполняем lesson_01/homework_01.md, кладём кадры в lesson_01/screens/
git add lesson_01
git commit -m "hw-01: три события, путь пользователя, точка потери данных"
git push -u origin hw-01
```

Дальше на GitHub открываете **Pull Request** в свою `main` и коротко пишете,
что сделано. Merge делаете сами после проверки.

Полный порядок, сроки, печать бланков в PDF и чек-лист перед отправкой —
[docs/SUBMIT.md](docs/SUBMIT.md).

## Структура

```
HOMEWORK_TEMPLATE.md   образец шапки работы и требования к оформлению
lesson_01/             задание 1: условия, бланк, папка screens/
lesson_02/             задание 2: условия, бланк, папка screens/
lesson_03/             задание 3: условия, бланк, папка screens/
docs/SUBMIT.md         порядок сдачи и чек-лист
docs/git/              разбор работы с git и GitHub со скриншотами
```

Папку для нового задания создаёте копией последней:
`cp -r lesson_03 lesson_04` (на Windows —
`Copy-Item -Recurse lesson_03 lesson_04`).

## Оформление: что проверяется всегда

| Требование | Как проверяется |
|---|---|
| Шапка бланка заполнена | ФИО, группа, номер работы, тема, дата, ветка |
| Формат | Markdown `.md`, имя файла из бланка задания |
| Расположение | папка своего задания, не корень репозитория |
| Скриншоты | PNG, в `screens/` рядом с бланком, имена из задания |
| Ссылки на кадры | `![подпись](screens/01-имя.png)` в тексте бланка |
| Пустые заготовки | удалены |
| Источники | полным адресом, ссылки рабочие |

## Что не кладём в репозиторий

- **Токены, ключи API, пароли, строки подключения.** Секреты живут
  в credentials store сервиса, а не в файлах и не в экспорте workflow.
- **Экспорт workflow с секретами внутри.** Выгружается очищенным.
- **Лишние персональные данные** в тестовых payload и на кадрах.

Файл `.gitignore` уже исключает частые опасные имена (`*.secret`,
`credentials*.json`, `.env`), но коммит перед отправкой проверяется глазами.

## Правила про ИИ

- ИИ можно использовать для поиска идей, структурирования и проверки
  формулировок.
- **Источником ИИ не считается.** Каждый факт, цифра и кейс — со ссылкой
  на исходный материал.
- Наблюдения в браузере, настройка сервисов и съёмка кадров — ваша работа.
- Придумывать показатели компаний запрещено. Если показатели
  не опубликованы, так и пишется: «точные показатели в открытом источнике
  не приведены».
- В каждом бланке есть раздел про использование ИИ — он заполняется честно.
- Работа из одного текста нейросети без источников, кейсов, ссылок,
  собственного анализа и скриншотов не принимается.
