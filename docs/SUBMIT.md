## Правило

**Одно задание — одна ветка — один запрос на слияние.** Ветка называется
по номеру задания. Работа не отправляется прямо в `main`: проверка идёт
по запросам на слияние.

## Шаги

```bash
git switch main
git pull                            # подтянуть слитые ранее работы
git switch -c hw-01                 # ветка по номеру задания
# заполняем бланк, кладём кадры в lesson_01/screens/
git add lesson_01
git commit -m "hw-01: пять событий, путь пользователя, точки потери данных"
git push -u origin hw-01
```

Дальше на GitHub: **Pull requests → New pull request**, base — своя `main`,
compare — `hw-01`. Описание подставится само из шаблона: заполните его
и отправьте. **Merge** делаете сами после проверки преподавателем.

То же самое делается мышкой в VS Code. Разбор со скриншотами:
[коротко](git/README.md), [подробно](git/FULL.md).

## Скриншоты

| Правило | Как надо |
|---|---|
| Формат | PNG |
| Где лежат | `lesson_NN/screens/` |
| Имена | из таблицы задания: `01-network.png`, `01-tag-detected.png` и так далее |
| Нумерация | по порядку упоминания в бланке |
| Ссылка в бланке | `![подпись](screens/01-tag-detected.png)` |
| Что видно на кадре | адрес своего сайта и свой Measurement ID — по ним сверяется, что работа своя |

Замазывать Measurement ID нельзя: по нему проверяется, что ресурс ваш.
Замазывать нужно личную переписку, чужие имена и адреса электронной почты
других людей, если они попали в кадр.

## Бланки в PDF

Заполненный бланк сдаётся в репозитории как `.md`. Если нужна печатная
версия — открыть файл на GitHub и напечатать страницу в PDF. В диалоге печати
снять галочку **«Колонтитулы»**, иначе браузер допишет дату и адрес страницы.

## Чек-лист перед push

- [ ] Шапка бланка заполнена: ФИО, группа, номер работы, тема, дата, ветка.
- [ ] Файлы лежат в папке своего задания, а не в корне.
- [ ] Все скриншоты из таблицы задания приложены и названы по образцу.
- [ ] Ссылки на кадры в бланке открываются.
- [ ] Пустые строки-заготовки из таблиц удалены.
- [ ] Ссылки на источники записаны полным адресом и работают.
- [ ] Заполнен раздел про использование ИИ.
- [ ] `git status` не показывает `.env`, `credentials*.json`, `*.secret`.
- [ ] Ветка названа по номеру задания, коммит описывает работу, а не «fix».

## Частые ошибки

**Работа ушла в `main` напрямую.** Создайте ветку от текущего состояния
и откройте запрос: `git switch -c hw-01` — незакоммиченные правки переедут
в новую ветку.

**Вторая работа попала в ветку первой.** Перед новым заданием возвращайтесь
на `main` и создавайте ветку оттуда.

**Скриншоты не добавлены в коммит.** Картинки не отслеживаются
автоматически. После `git add` проверьте `git status`: файлы из `screens/`
должны быть в списке.

**Ссылка на кадр не открывается.** Имя файла в бланке и на диске совпадает
посимвольно, включая регистр и расширение.
