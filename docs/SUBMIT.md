# Порядок сдачи

Одна страница на всю дисциплину. Что именно сдавать по конкретному занятию —
в `README.md` внутри его папки.

## Правило

**Одно задание — одна ветка — один запрос на слияние.** Ветка называется
по номеру папки занятия, а не по номеру задания: так две работы никогда
не попадут в одну ветку.

| Занятие | Папка | Первое задание | Исследовательское задание |
|---|---|---|---|
| Вводное | `lesson_01` | `homework_01.md` · ветка `hw-01` | — |
| Цифровая воронка | `lesson_02` | `homework_01.md` · ветка `hw-02` | `research_01.md` · ветка `hw-02-research` |
| UTM-метки | `lesson_03` | `homework_02.md` · ветка `hw-03` | `research_02.md` · ветка `hw-03-research` |
| Google Analytics 4 | `lesson_04` | задания нет, сдаётся `ga4_setup.md` на паре | — |
| Свой сайт и Google Tag | `lesson_05` | задания нет, сдаётся `site.md` на паре | — |

Имена файлов домашних заданий совпадают с теми, что названы на слайде
занятия. Номер в имени файла и номер папки различаются: файл нумеруется
по занятию, к которому задание выдано.

## Шаги

```bash
git switch main
git pull                            # подтянуть слитые ранее работы
git switch -c hw-02                 # ветка по номеру папки
# заполняем файлы в lesson_02/
git add lesson_02
git commit -m "hw-02: журнал событий на втором сайте, сравнение, гипотеза"
git push -u origin hw-02
```

Дальше на GitHub: **Pull requests → New pull request**, base — своя `main`,
compare — `hw-02`. В описании коротко: что сделано, где данные теряются,
что проверяли. **Merge** делаете сами после проверки преподавателем.

То же самое делается мышкой в VS Code, без терминала. Разбор со скриншотами:
[коротко](git/README.md), [подробно](git/FULL.md).

## Срок

Первое задание — до начала следующего занятия. Исследовательское — срок
согласуется с преподавателем, обычно два-три занятия, и к нему добавляется
доклад на паре.

## Бланки в PDF

Заполненный бланк сдаётся в репозитории как `.md`. Если нужна печатная
версия — открыть файл на GitHub и напечатать страницу в PDF. В диалоге печати
снять галочку **«Колонтитулы»**, иначе браузер допишет дату и адрес страницы.

## Чек-лист перед push

- [ ] Файлы лежат в папке своего занятия, а не в корне.
- [ ] Заполнены поля **Студент** и **Группа** в каждом бланке.
- [ ] В таблицах нет пустых строк-заготовок: лишние удалены.
- [ ] Ссылки записаны целиком, а не «как в строке 3».
- [ ] Кадры приложены и названы понятно, ссылки на них в бланке работают.
- [ ] `git status` не показывает `.env`, `credentials*.json`, `*.secret`.
- [ ] В экспортах и на кадрах нет токенов, ключей и чужих персональных данных.
- [ ] Ветка названа по номеру папки, коммит описывает работу, а не «fix».

## Частые ошибки

**Работа ушла в `main` напрямую.** Проверка идёт по запросам на слияние.
Создайте ветку от текущего состояния и откройте запрос:
`git switch -c hw-02` — незакоммиченные правки переедут в новую ветку.

**Вторая работа попала в ветку первой.** Перед новым заданием всегда
возвращайтесь на `main` и создавайте ветку оттуда.

**Забыт `git add` для кадров.** Картинки не отслеживаются автоматически.
После `git add` проверьте `git status`: приложенные файлы должны быть
в списке.
